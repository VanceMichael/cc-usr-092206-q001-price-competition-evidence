# 低价竞争执法证据链 · 办案服务

面向市场监管部门常态化监管的低价竞争案件办案系统：维护从线索、立案、取证、
申辩、处罚到整改复核的**完整、可解释、可重现、可核验**的证据链。

- **可解释**：承办人随时能说明锁定的调查范围与当前取证缺口；
- **可重现**：复核人员按处罚决定钉住的序号与哈希重放，还原处罚所依据的确切版本；
- **可核验**：整改完成后用**同一批产品、同一时段**核验风险是否真正消除。

零第三方依赖，仅需 Python 3.11+ 标准库。

## 领域规则如何落地

| 题目要求 | 系统约束 |
| --- | --- |
| 立案时锁定商品规格、活动范围、当期成本标准 | `open_case` 一次性锁定；成本标准适用期必须覆盖活动期；之后不可改写 |
| 不同时间口径的价格不能互相覆盖 | 促销价/日常价/促前价/平台补报/整改复核价分口径留存；补报只能追加，且必须显式标注「平台补报」 |
| 平台补报、跨地区移送、口径修订、规则下线只能追加 | 全部为独立事件类型，追加到案件哈希链；口径保留完整修订史，规则下线不可重复 |
| 清仓还是倾销不能只凭一个数字 | 价费比 = 促销成交均价 ÷ 当期单位成本；低于成本还须排除"限期内+附库存佐证"的清仓申辩 |
| 企业可在限期内申辩 | 告知时设定截止日；是否逾期由系统按提交日判定，逾期申辩仍登记但不采纳 |
| 商业秘密按案件授权开放 | 授权范围、期限、撤销全程留痕；`visible_evidence` 按查阅人与日期判定可见性 |
| 质量风险触发抽查/召回协作 | 重点品类价低缺抽检为阻断缺口；抽检不合格自动提示下架、批次追溯与召回协作 |
| 复核人员重现处罚版本 | 处罚决定钉住决定前的链头序号+哈希、口径快照、有效规则集合；按序号重放即可还原 |
| 整改后同批产品同时段核验 | 整改计划强制复用原 SKU 与原活动时段；复核价单列为「整改复核价」，不污染处罚均价 |

## 模块结构

```
src/
  models.py   商品规格、活动范围、成本标准、各口径价格、抽检、申辩、线下交易等模型
  ledger.py   仅追加哈希链账本（InMemoryLedger / FileLedger，JSONL 持久化，篡改即检出）
  state.py    事件折叠：重放到任意序号，还原当前或历史版本
  policy.py   纯规则：价费比对、取证缺口、质量风险联动、整改核验
  service.py  命令面：全流程唯一写入口，阶段守卫与业务校验
  reports.py  三份报告：调查范围与缺口 / 处罚版本重现 / 整改核验
  demo.py     一个家电低价倾销案件的端到端示例
  cli.py      命令行日常入口
```

### 事件溯源（append-only 哈希链）

每个案件一条独立 SHA-256 哈希链：`hash(n) = H(内容 + prev_hash)`，首事件前驱为
`GENESIS`。任何插入、删除、重排、篡改都会在 `verify` 时暴露；文件账本在被破坏的
链尾继续追加也会被拒绝。事件只增不改——"修订"就是追加一条修订事件。

## 命令行用法

```bash
# 一键演示完整案件并打印三份报告
python -m src.cli demo --store data/cases

# 日常查询
python -m src.cli list   --store data/cases
python -m src.cli verify --store data/cases            # 哈希链自检（全部案件）
python -m src.cli scope      demo-2026-001 --store data/cases          # 调查范围+缺口
python -m src.cli reproduce  demo-2026-001 --store data/cases          # 处罚版本重现
python -m src.cli rectify    demo-2026-001 --store data/cases          # 整改核验
# 以上报告均可加 --json 输出结构化结果

# 批量写入：按动作文件（建议随案卷归档）
python -m src.cli apply actions.json --store data/cases
```

动作文件形如：

```json
{
  "case_id": "batch-001",
  "actions": [
    {"op": "register_lead", "args": {"summary": "…", "occurred_on": "2026-03-02"}},
    {"op": "open_case", "args": {"products": […], "scope": {…}, "cost_standard": {…}, "occurred_on": "2026-03-03"}}
  ]
}
```

字段名与 `src.service.CaseService` 的方法参数一致；违反阶段守卫或业务约束的动作
会被整体拒绝并返回退出码 2。

## 三份报告回答三个问题

1. **调查范围与取证缺口**（承办人）：锁定了哪些商品规格/渠道/地区/时段、当期成本，
   各 SKU 价费比与清仓认定，以及按"阻断 / 重要 / 提示"分级的缺口清单。
2. **处罚版本重现**（复核人员）：决定编号、钉住的序号与哈希、口径快照、钉住时
   仍有效的平台规则、引用证据，并列出处罚后追加的修订与下线（不影响已钉住版本）。
3. **整改核验**（闭环）：同批 SKU、同一时段；按期提交、复核价不低于成本、原不合格
   项目全部复检合格、违规规则已下线留痕，逐项给出通过/不通过。

## 阶段流转

```
线索 → 已立案 → 申辩期 → 已结案 → 已核验
        （范围锁定）  （限期申辩） （处罚钉版） （同批同时段复核）
```
